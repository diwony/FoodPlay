FoodPlay 기획 & 설명서

냉장고 재료로 만들 수 있는 유튜브 요리 영상을 찾고,
조리 스텝의 타임스탬프를 눌러 그 장면으로 바로 이동하는 서비스입니다.

0. 뭐 해먹지, 에서 시작했어요

문제 · 해결 · 대상 · 스택

문제
냉장고에 재료는 있는데 ‘뭘 해먹지’에서 막혀 결국 배달앱을 켜요. 유튜브에 요리 영상은 많지만, 조리 중에 ‘지금 그 단계’를 다시 찾으려면 영상을 앞뒤로 스크럽해야 하고, 영상마다 필요한 재료가 뭔지도 미리 알기 어려워요.
해결
가진 재료(또는 그날의 기분 · 상황)를 넣으면 만들 수 있는 유튜브 요리 영상을 메뉴 단위로 찾아줘요. 조리 스텝마다 타임스탬프를 붙여서, 누르면 영상이 바로 그 장면으로 이동해요. 큐레이션되지 않은 검색 결과 영상도 설명글 · 자막을 읽어 ‘냉장고에 이런 게 있어야 해요’ 체크리스트를 만들어 줘요.
누구를 위한 것 · 범위
자취생 · 1인가구 · 직장인처럼 ‘장은 봤는데 요리는 부담’인 사람을 위한 거예요. 계정 없이 기기(localStorage)에만 저장해요. 1인 개인 포트폴리오 프로젝트로 기획 · UX/UI · 프론트엔드 · 데이터 파이프라인 전 과정을 직접 했고, 웹(주력)과 모바일 앱을 같은 로직으로 함께 만들었어요.
핵심 특징 3가지
  • 유튜버가 아니라 ‘메뉴 단위’ 큐레이션 — 실시간 인기도 메뉴로 매겨요.
  • 타임스탬프 시크 — 웹 · 앱이 동일한 seekTo / pause 계약을 공유해요.
  • 2층 데이터 — 미리 수집한 11,000+ 영상 풀(1층) 위에 실시간 유튜브 결과(2층)를 얹고, 실시간이 안 되면 1층으로 조용히 폴백해서 화면이 비지 않아요.
스택 (요약)
공유 로직
@foodplay/core — 순수 TS · 의존성 0. 재료 정규화 · 매칭/랭킹 · vibe · 페르소나 · 절약 추정 · 계절/트렌드. 웹 · 앱이 그대로 공유.
웹 (주력)
Vite + React 19 + React Router + Tailwind v4 (apps/web)
모바일 앱
Expo + React Native 0.86 + Expo Router (저장소 루트, 네이티브 빌드용)
영상
웹: YouTube IFrame Player API + 네이버TV iframe / 앱: react-native-youtube-iframe (동일한 seekTo · pause 계약)
실시간 (2층)
Cloudflare Workers 프록시 — /search · /video · /transcript. API 키는 wrangler secret, 결과는 24시간 캐시.
데이터 (1층)
빌드 타임 큐레이션 recipes.json(25개) + 파이프라인이 공식 Data API v3로 수집한 유튜브 영상 풀(11,000+).
데이터 파이프라인
사람이 고른 영상 + 자막 + 상위 댓글 └─▶ pipeline/build.mjs · Claude(claude-sonnet-5) 자막 → 스텝 · 타임스탬프 / 재료 / vibe / 댓글 요약 └─▶ pipeline/validate.mjs 스키마 + 타임스탬프 단조 증가 검증 └─▶ packages/core/src/data/recipes.json (정적, 커밋) ← 웹 · 앱은 이 JSON만 읽음

1. 데스크톱 웹

Desktop · 뷰포트 1440px · 본문 컬럼 max 1024px

1-1 홈 (발견 홈) · /

레이아웃

상단 고정 헤더(로고 = 홈으로). 히어로 문구와 ‘사 먹을 때보다 평균 N원 아껴요’ 아래 2단 그리드 — 왼쪽은 ‘오늘은 이거 어때요?’ 추천 카드(DailyHero), 오른쪽 컬럼은 실시간 인기 요리 티커 · 이번 달 제철 미니 칩 · 어떤 분이세요? 페르소나 카드. 그 아래 4개 시작 모드 카드(냉장고 · 밀키트 · 장보기 · 디저트), 맨 아래 ‘🔥 요즘 뜨는’ 가로 레일과 ‘이런 것도 있어요’ 썸네일 그리드.

버튼 · 클릭 반응
  • DailyHero — 추천 카드 안에 관련 영상 썸네일이 바로 4칸 뜨고, 아래에 ‘▶ 추천 영상 보기’ · ‘내 재료로 찾기’ 버튼. 4초마다 추천이 자동으로 넘어가고(상단 점 인디케이터 이동), 마우스를 올리면 회전이 멈춰요. 점을 누르면 그 추천으로 이동. (모바일은 좌우 스와이프.) 화살표 버튼은 없어요.
  • 실시간 인기 요리 티커 — 평소엔 2.8초마다 한 줄씩 넘어가고, 마우스를 올리거나 누르면 전체 순위(최대 8개)가 아래로 펼쳐져요(▼ / ▲). ‘상승’ 뱃지. 항목을 누르면 그 메뉴의 대표 영상으로.
  • 제철 재료 칩 — 누르면 그 재료 + 내가 저장해둔 재료를 합쳐 냉장고 모드 결과로.
  • 페르소나 칩(6개: 자취생 · 1인가구 · 직장인 · 커플·신혼 · 주부 · 다이어터) — 누르면 홈 전체(모드 순서 · DailyHero 추천 구성)가 즉시 그 사람 맞춤으로 재배치되고, 첫 모드 카드에 ‘○○ 추천’ 뱃지, DailyHero에 ‘○○ 맞춤’ 뱃지가 붙어요. (기기에 저장.)
  • 모드 카드 4개 — ‘재료 고르기 →’ 등 CTA. 누르면 해당 모드로.
화면 전환

모드 카드 → /fridge · /mealkit · /shop · /dessert. 큐레이션 영상 썸네일 → /recipe/:id, 유튜브 결과 썸네일 → /yt/:id. 로고 → /.

구현 — DailyHero 회전은 4초 setInterval(hover / focus / touch 시 일시정지), 가로 레일 드래그는 useDragScroll 훅(마우스 드래그 · 세로 휠 → 가로 스크롤 변환). 페르소나 · 기분에 따른 재랭킹은 @foodplay/core의 순수 함수(웹 · 앱 공유). 추천 영상 · 인기 순위 · 트렌드는 미리 수집한 정적 풀에서 계산하고, 프록시가 있으면 실시간으로 갱신해 ‘실시간’ 배지를 답니다.

1-2 냉장고 재료로 만들기 · /fridge

레이아웃

제목 · 설명 아래 입력 카드: 재료 자유 입력창 + 그룹별 재료 칩(육류·계란 · 어류·해산물 · 채소·버섯 · 과일 · 김치·장·밥·떡 · 요즘 뜨는) + ‘내가 자주 쓰는 재료’(직접 추가 · × 삭제). 구분선 아래 ‘오늘 기분 · 상황’ 칩. 그 아래 결과 목록과 ‘같이 보는 먹방’ 레일.

버튼 · 클릭 반응
  • 재료 칩을 누르면 채워짐(✓ · 어두운 배경)으로 토글되고, 입력창 텍스트와 양방향으로 동기화돼요.
  • 기분 칩은 여러 개 토글. 문장으로 써도(‘비 와서 으슬으슬해’) 키워드로 기분을 인식해요.
  • 재료 · 기분을 바꿀 때마다 결과가 즉시 갱신되고, 결과 제목 옆에 총 개수, 오른쪽에 작은 카운트(‘재료 3 · 기분 1’)가 떠요.
  • 결과 목록은 큐레이션 레시피 카드와 유튜브 영상 카드를 한 그리드에 이어서 보여줘요(둘 다 있으면 ‘📖 스텝 정리된 레시피 / ▶ 영상’ 안내 한 줄). 큐레이션 레시피가 없는 재료를 골랐으면 제목이 ‘유튜브에서 찾아봤어요’로 바뀌고 영상만 떠요.
화면 전환

헤더 ‘← 다른 방식으로’ → /. 레시피 카드 → /recipe/:id. 유튜브 · 먹방 카드 → /yt/:id.

구현 — 재료 정규화 · 매칭 · 랭킹은 전부 @foodplay/core(의존성 0). 입력은 useDeferredValue로 타이핑 렌더와 결과 계산을 분리. 관련 영상은 런타임 호출 없이 정적 풀을 태그로 걸러 채우고, 프록시가 있으면 실시간 결과를 위에 얹어요.

1-3 밀키트 푸짐하게 보충 · /mealkit

레이아웃

카드 상단 ‘어떤 밀키트예요?’ 프리셋 칩(밀푀유나베 · 부대찌개 · 마라탕 등 19종) + 직접 추가. 구분선. ‘집에 있는 재료 더하기’ 칩(치즈 · 계란 · 라면사리 등) + 직접 추가. 밀키트를 고르기 전엔 안내 문구만, 고르면 ‘이렇게 만들어 먹어요’ 영상 레일 + ‘○○ 먹방’ 레일.

버튼 · 클릭 반응
  • 밀키트 칩은 라디오식 — 하나만 선택되고 다시 누르면 해제.
  • 더할 재료 칩은 여러 개 토글.
  • 선택 즉시 아래 영상 검색어가 ‘부대찌개 라면사리 활용 요리’처럼 조합되어 레일이 채워져요.
화면 전환

헤더 → /. 영상 카드 → /yt/:id.

구현 — 밀키트 + 더한 재료 상태로 유튜브 검색어를 조립. 결과 레일은 수집해 둔 영상 풀에서 재료 태그로 필터하고, 부족하면 검색 링크로. 직접 추가한 밀키트 · 재료는 localStorage에 저장.

1-4 장보기 추천 · /shop

레이아웃

제목 아래 필터 카드: 직접 입력창(인식된 기분 표시) + 칩 그룹 6개 — 날씨 · 예산(장바구니) · 땡기는 맛 · 누구랑·몇 인분 · 요리 계열 · 메뉴 종류. 그 아래 결과 목록(카드마다 장바구니 예산 + 살 재료 목록 🛒) + 유튜브 · 먹방 레일.

버튼 · 클릭 반응
  • 날씨는 단일 선택, 나머지 5개 그룹은 다중 토글(선택 시 초록).
  • 조건을 더할수록 결과가 좁혀지고 ‘조건 N’ 카운터가 떠요(입력창도 1로 셈).
  • 직접 입력에 ‘비 오는데 얼큰한’처럼 쓰면 기분(#얼큰 등)을 자동 인식.
  • 조건에 맞는 큐레이션이 없으면 ‘유튜브에서 같은 조건으로 찾아드릴게요’로 대체.
화면 전환

헤더 → /. 레시피 카드 → /recipe/:id. 유튜브 카드 → /yt/:id.

구현 — 칩 조건으로 큐레이션(recipes.json)을 클라이언트에서 필터, 부족하면 유튜브 풀 → 실시간 순으로 넘어감. 예산 추정도 @foodplay/core 함수.

1-5 디저트 · 베이킹 · /dessert

레이아웃

카드: ‘어떻게 만들까요?’ 3개 방식 버튼(본격 베이킹 / 간단 베이킹 / 음료·아이스크림) · ‘집에 있는 재료’ 칩 그룹(베이킹 가루·재료 · 냉장고 · 서랍·팬트리 · 과일·얼음)과 ‘내가 넣을 재료’ 직접 추가 · ‘🔥 요즘 뜨는 디저트’ 칩(두바이 초콜릿 · 크로플 · 마리토쪼 등). 아래 ‘○○ 영상’ 유튜브 레일 + ‘디저트 먹방’ 레일.

버튼 · 클릭 반응
  • 방식 버튼과 트렌드 칩은 라디오식(하나만, 다시 누르면 해제). 아무것도 안 고르면 다 보여줘요.
  • ‘요즘 뜨는 디저트’를 고르면 재료 칩 그룹이 흐려지며 비활성(‘잠깐 꺼져요’ 안내).
  • 재료 칩을 고르면 검색어가 ‘딸기 노오븐 디저트’처럼 조합돼요.
화면 전환

헤더 → /. 영상 카드 → /yt/:id. (레시피 화면 하단 배너에서 넘어올 땐 /dessert?level=easy로 방식이 미리 선택됨.)

구현 — ‘요즘 뜨는 디저트’ 칩은 파이프라인 수집 태그와 1:1로 맞춤. 방식 · 재료 · 트렌드 상태에서 유튜브 검색어와 필터 태그를 만들어 풀에서 거릅니다.

1-6 레시피 재생 (큐레이션) · /recipe/:id

레이아웃

상단 16:9 유튜브 플레이어. 숏폼이 있는 레시피면(25개 중 18개) 롱폼/숏폼 토글. 제목 · 채널 · 메타 칩(시간 · 난이도 · 계열 · 인분 · 추가 재료 수). ‘N원 아껴요’ 절약 박스. ‘필요한 추가 재료’ 칩. ‘조리 순서’ — 스텝마다 ▶ 타임스탬프 버튼 + 설명. ‘영상 댓글 반응’ 요약. ‘블로그 레시피’. ‘추천 영상’ 레일. 하단에 디저트 유도 배너 + ‘유튜브에서 전체 영상 보기 ↗’.

버튼 · 클릭 반응
  • ▶ 시간 버튼을 누르면 영상이 그 초로 즉시 이동(seekTo).
  • 페이지를 스크롤하면 플레이어가 화면 상단 중앙에 고정되는 미니 플레이어로 축소돼요 — 위치는 그대로, 크기만 재생 영상 폭의 80%(최대 480px, 16:9 유지)로.
  • 미니 플레이어는 마우스로 끌어 옮길 수 있고(유튜브 프리미엄식), 놓으면 가까운 좌/우 가장자리로 붙어요. 4px 미만으로 살짝 누르면 펼쳐지고(맨 위로 스크롤), 미니 상태에서 시간 버튼을 눌러도 자동으로 펼쳐져요. ✕를 누르면 닫히고 재생 정지.
  • 롱폼/숏폼 토글 — 숏폼(유튜브 쇼츠 · 네이버TV)은 세로 프레임이 되고 미니화는 없어요. 네이버TV는 임베드 대신 외부 링크. (?v=short로 들어오면 숏폼으로 바로 열림.)
화면 전환

‘추천 영상’ → 다른 /recipe/:id. 블로그 · ‘유튜브에서 전체 영상 보기 ↗’ → 외부 새 탭. 하단 배너 → /dessert?level=easy. 헤더 ‘← 처음으로’ → /.

구현 — 플레이어는 YouTube IFrame Player API(useYouTube). 미니 전환은 슬롯 위치만 읽어 같은 노드의 CSS 클래스만 바꾸는 useMiniPlayer(iframe을 DOM에서 옮기지 않아 재생이 안 끊김), 드래그는 useMiniDrag(PointerEvent + setPointerCapture → 놓으면 좌/우 스냅). 구간 이동은 player.seekTo(초) 한 줄.

1-7 유튜브 검색 결과 재생 · /yt/:id

레이아웃

플레이어 아래 ‘같은 재료로 나온 유튜브 영상’ 라벨 + 제목 · 채널 · 조회수. ‘냉장고에 이런 게 있어야 해요’ 재료 체크리스트(내가 등록한 재료는 초록 ✓). 영상 설명글에 따라 ‘정확한 계량’, ‘조리 순서 · 타임라인’(설명글 챕터) 또는 번호 순서가 뜨고, 없으면 안내 문구. ‘영상 설명’ 펼치기. ‘유튜브에서 보기 ↗’. ‘이어서 볼 만한 영상’ 그리드.

버튼 · 클릭 반응
  • 큐레이션이 아니라 미리 수집한 풀(1층) + 실시간 유튜브(2층) 데이터를 합쳐 보여주므로, 영상마다 표시되는 섹션이 달라요.
  • 타임라인 ▶ 시간 버튼 → seekTo. 스크롤하면 레시피 화면과 똑같이 미니 플레이어로 축소(상단 중앙 고정 · 드래그 이동).
  • ‘영상 설명’은 펼치기 ▼ / 접기 ▲ 토글.
화면 전환

‘이어서 볼 만한 영상’ → 다른 /yt/:id. ‘유튜브에서 보기 ↗’ → 외부. ‘← 처음으로’ → /.

구현 — 실시간 검색 · 영상 상세 · 자막은 Cloudflare Workers 프록시 경유(API 키는 wrangler secret). 설명글에서 챕터 · 계량 · 재료를 정규식으로 파싱하고, 없으면 자막(CC)에서 재료를 추출. 재료 체크리스트는 설명글 + 자막 + 풀 태그를 합쳐 만듭니다.

2. 모바일 웹

Mobile Web · 뷰포트 390px

공통 규칙 (데스크톱과 다른 점)
  • 데스크톱의 2단 그리드 → 세로 1단 스택. 결과 카드 2열 → 1열.
  • 마우스 호버 효과 대신 탭. 칩 · 버튼 터치 타깃이 커짐.
  • 재료 그룹 칩 · 필터 칩은 여러 줄로 줄바꿈. 세로 스크롤 길이만 늘어남.
  • 가로 레일은 손가락 스와이프. DailyHero 추천 카드도 좌우 스와이프로 전환.
  • 미니 플레이어 동작은 데스크톱 웹과 동일 — 상단 중앙 고정, 크기만 축소, 끌어서 이동 → 놓으면 좌/우 스냅(터치).

기능 · 로직 · 라우팅은 데스크톱 웹과 완전히 같습니다. 아래는 레이아웃이 실제로 달라지는 지점만.

2-1 홈 · /

2단 그리드가 세로 1단으로 스택 — 추천 카드 → 실시간 인기 요리 → 이번 달 제철 → 페르소나 → 4개 모드 카드(1열) → ‘요즘 뜨는’ 레일 · 탐색 그리드 순.

2-6 레시피 재생 · /recipe/:id  /  2-7 유튜브 결과 · /yt/:id

플레이어가 상단 풀폭 16:9. 그 아래 섹션 순서는 데스크톱과 같음. 미니 플레이어 · 타임스탬프 시크 · ‘영상 설명’ 펼치기 동작 모두 동일. ‘이어서 볼 만한 영상’ 그리드가 2열. 숏폼(쇼츠 · 네이버TV)은 세로 프레임, 네이버TV는 링크로 열림.

3. 모바일 앱

Expo · React Native · Expo Router

왜 앱은 화면이 2개뿐인가요?
웹은 라우트가 7개지만, 앱은 app/_layout.tsx의 Stack에 index(홈) · recipe/[id](레시피) 2개만 있습니다. 미완성이 아니라 설계 차이 — 웹에서 페이지로 나뉜 4개 시작 모드(냉장고 · 밀키트 · 장보기 · 디저트)를 앱은 홈 화면 하나(재료 입력 중심 단일 스크롤)로 합쳤고, ‘유튜브 검색 결과 재생(/yt/:id)’에 해당하는 화면은 앱에 없습니다(앱은 큐레이션 레시피만 재생).

3-1 홈 · app/index.tsx

레이아웃

네이티브 스택 헤더(‘FoodPlay’). 화면 전체가 하나의 스크롤 리스트: 히어로 문구 → ‘오늘은 이거 어때요?’ 추천 카드 → ‘어떤 분이세요?’ 페르소나 칩 → 재료 자유 입력창 → 그룹별 재료 칩 → ‘내가 자주 쓰는 재료’(직접 추가 · × 삭제) → ‘오늘 기분 · 상황’ 칩 → (재료·기분을 고르면) ‘재료 N개 · 기분 M개 · 레시피 K개 매칭’ 카운트 → 결과 카드 목록 → ‘＋ 더보기 N개’.

버튼 · 클릭 반응
  • 추천 카드를 좌우로 스와이프해 전환(10px 미만은 탭으로 처리 → 그 기분으로 검색). 4초마다 자동으로 넘어감.
  • 재료 · 기분 · 페르소나 칩은 탭으로 토글(선택 시 ✓ · 색 반전).
  • 페르소나를 처음 고르면 기분도 그 사람 기본값으로 채워짐.
  • ‘＋ 더보기’를 누를 때마다 6개씩 더 보임.
화면 전환

결과 카드를 탭 → 레시피 화면(recipe/[id]). 키보드가 뜬 채 스크롤하면 자동으로 내려감.

웹과 다른 점

웹 홈의 ‘발견형’ 레일 · 그리드(인기 요리 티커 · 제철 · 요즘 뜨는 · 탐색 그리드) 대신, 재료 입력 중심의 단일 리스트. 데스크톱 웹의 4개 모드 분리 화면은 없고 이 한 화면에 통합.

구현 — 화면 전체가 FlatList 하나. 추천 카드 스와이프는 PanResponder(10px 미만 움직임은 탭). 매칭 · 랭킹은 웹과 같은 @foodplay/core.

3-2 레시피 재생 · app/recipe/[id].tsx

레이아웃

스택 헤더(레시피 제목 · ‘뒤로’). 상단에 유튜브 플레이어, 숏폼이 있으면 롱폼/숏폼 토글. 제목 · 채널 · 메타 칩 · ‘N원 아껴요’ · 추가 재료 칩 · 조리 순서(▶ 시간 + STEP) · 댓글 반응 · 블로그 · 추천 영상 · ‘유튜브에서 전체 영상 보기 ↗’ — 웹과 같은 구성.

버튼 · 클릭 반응
  • ▶ 시간 버튼을 탭하면 영상이 그 초로 이동(seekTo).
  • 스크롤하면 플레이어가 스크롤 양에 따라 위치 · 크기가 부드럽게 보간되며 화면 우상단 구석으로 미끄러져 축소됨(폭 약 72% · 최대 300px).
  • 미니를 탭하면 맨 위로 스크롤하며 펼쳐지고, ✕로 닫으면 재생 정지. 다시 위로 올리면 미니가 재등장. (앱의 미니 플레이어는 끌어서 옮길 수 없음.)
화면 전환

추천 영상 탭 → 다른 recipe/[id]. 블로그 · ‘유튜브에서 보기 ↗’ → 기기 브라우저 / 유튜브 앱. 네이버TV 숏폼은 임베드 대신 외부 링크. 헤더 ‘뒤로’(또는 뒤로 제스처) → 홈.

웹과 다른 점

미니 플레이어가 스크롤에 따라 화면 우상단 구석으로 미끄러지며 축소되고, 드래그 이동은 지원하지 않음 — 웹(데스크톱 · 모바일)은 상단 중앙 고정 + 끌어서 이동(놓으면 좌/우 스냅). 그 외 네이티브 스택 내비게이션 · 뒤로가기 제스처를 사용.

구현 — react-native-youtube-iframe 사용(웹 IFrame API와 같은 seekTo / pause 계약). 미니 전환은 Animated.Value + interpolate로 top · left · width · height를 보간 — transform 대신 실제 좌표를 써서 터치 히트영역이 정확.

4. 설치형 배포

PWA & Android APK

웹앱(apps/web)을 그대로 설치형으로 배포했습니다 — 별도 네이티브 코드 없이 iOS · Android · PC 어디서나 ‘앱처럼’ 쓰게. (저장소 루트의 Expo/RN 앱은 네이티브 빌드용으로 따로 있습니다 — 3번 섹션.)

apps/web (Vite · vite-plugin-pwa) └─▶ diwony.github.io/FoodPlay/ (gh-pages, 배포된 PWA) └─▶ PWABuilder (TWA로 포장) ─▶ FoodPlay.apk ─▶ GitHub Releases (releases/latest · README QR) ＋ diwony.github.io/.well-known/assetlinks.json 이 사이트 ↔ 앱을 상호 인증(Digital Asset Links) → APK 실행 시 상단 주소창 제거 (Google 검증 linked: true)
PWA (설치형 웹앱)

vite-plugin-pwa로 매니페스트 + 서비스워커(autoUpdate) 생성. 매니페스트: 이름 ‘FoodPlay — 냉장고 재료로 요리 영상 찾기’(short_name ‘FoodPlay’), display: standalone, orientation: portrait, 테마색 #FBFAF7, 아이콘 192 / 512 / maskable. 서비스워커는 앱 셸 · 정적 자산(js · css · html · svg · png · woff2)을 프리캐시하고, 큰 youtube-pool.json은 프리캐시에서 빼고 StaleWhileRevalidate로, 모든 딥링크(/yt/:id 포함)는 index.html로 폴백해 React Router가 처리. → iOS Safari ‘홈 화면에 추가’, Android Chrome ‘앱 설치’ 배너, PC 브라우저 설치.

Android APK (TWA)

위 PWA를 PWABuilder로 감싼 TWA(Trusted Web Activity) 패키지. Google Play 계정도, 서명 인증서 구매도 필요 없이 무료. 서명 키는 PWABuilder가 생성 → 잃어버리면 업데이트 배포 불가라 저장소 밖에 따로 보관(.gitignore에 *.keystore · *.apk 차단). 배포는 GitHub Releases(releases/latest) — README 오른쪽 QR이 항상 최신을 가리킴.

주소창 제거 — Digital Asset Links

APK를 스토어 밖에서 설치하면 기본적으로 상단에 Chrome 주소창이 뜬다. 도메인 루트의 /.well-known/assetlinks.json으로 앱↔사이트를 서로 인증하면 사라진다. GitHub Pages 프로젝트 사이트(diwony.github.io/FoodPlay/)는 /.well-known/을 못 내보내므로, 도메인 루트를 서빙하는 별도 저장소 diwony/diwony.github.io가 이 파일을 올린다. Google 검증 API 결과 linked: true.

업데이트 · iOS

웹 내용만 바뀌면 npm run deploy:web 한 번이면 APK 안에서도 최신 웹이 뜬다(TWA는 껍데기라 새로 빌드할 필요 없음). 아이콘 · 이름 · 매니페스트가 바뀔 때만 같은 서명 키로 재패키지. iOS는 자유 배포가 불가능(App Store 연 $99)해서, iOS 사용자는 Safari ‘홈 화면에 추가’로 같은 PWA를 설치한다.
